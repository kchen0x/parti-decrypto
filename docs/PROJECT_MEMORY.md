# 项目记忆

## 项目目标

让朋友在 Parti 中随时创建《截码战》房间，进行 4–8 人的两队文字密码对抗；不依赖自建服务器或第三方游戏后端。

## 关键实现决策

| 决策 | 原因 |
| --- | --- |
| `snapshot` 同步 | Parti 当前实际生效的同步模式；Worker 改动 state 后 Runtime 自动广播。 |
| 4–8 人、每队 2–4 人 | 对应标准双队体验，且 manifest 与 Worker meta 一致。 |
| 单轮顺序传讯 | 避免两个队伍同时输入造成移动端协调困难，同时保留核心编码、解码与截获机制。 |
| `secrets` 模块私有变量 | 防止关键词、当前代码、未公开猜测进入公开 state。 |
| `ctx.send()` 私密下发 | 队伍关键词只发给队友；当前代码只发给当前编码员。 |
| 房主恢复时回到大厅 | Worker 私密内存不会随持久化快照恢复；主动重置比带着已丢失的秘密继续游戏安全。 |
| 90 秒编码、60 秒猜测的软性倒计时 | 给玩家节奏提示，但不以倒计时自动结算；只有完成三条线索或双方猜测提交才推进回合。 |
| 对局 UI 的渐进披露 | 每局私密密钥默认折叠；开局后隐藏开场信息；房主控制只在右上角齿轮菜单内出现，避免干扰或误触。 |
| 桌游化视觉语言 | 阵营角色、密码牌和封面均为包内原创贴图；贴图在大厅、战况、传讯、私钥间复用，动效只强化节奏，且尊重减少动态效果偏好。 |
| 静态优先的性能预算 | 任务垫、信号线路和私钥印章等静态贴图替代循环动效；禁止 500ms 全区重渲染。倒计时仅更新单一文本节点，页面后台时暂停。 |
| 代码牌用尽判定 | 为极端的无终局对局提供确定、可解释的结束条件。 |
| 包内原创封面 | `assets/cipher-clash-cover.jpg` 由 manifest `cover` 引用，供房间市场卡片与仓库首页展示；因此 packageMode 使用 `filesystem`。 |

## 不可破坏的不变量

1. `state.turn` 中绝不能出现当前真实代码、未公开猜测，或未公开的单条线索。
2. 当前代码只能经 `decrypto:private` 发给 `turn.encoderId`。
3. 解码和截获猜测在双方都提交前只以布尔提交状态出现在 state 中。
4. 客户端的本地变量仅用于输入和渲染；不用于裁决输赢。
5. `onRestore`、游戏中 `onLeave` 都必须清除 Worker 私密数据并回到大厅。
6. 自定义事件不得使用 `sys:`、`state:` 或 `__error` 前缀。
7. `deadline` 仅为客户端节奏提示；不得重新引入定时器在时间到零时改变 `phase`、计分或公开秘密。

## 已知边界

- Parti 的 Host Authoritative 不是对恶意房主的反作弊保证；本游戏面向朋友间的轻量娱乐。
- 房间不是 24/7 云端服务：房主关闭页面后，本局结束。
- 语义上“线索是否恰当”无法自动验证；Worker 只能禁止数字、控制字符和直接包含对应关键词。
- 房间源代码会发给参与者；私密性依赖 Worker 运行时状态而非防篡改安全边界。
